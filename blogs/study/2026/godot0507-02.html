玩家斜方向移动时场景抖动

悯 2026-05-07 15:30:00 godotgame

# 问题记录：玩家斜方向移动时场景抖动

# 问题现象

  • 表现：玩家斜方向行走时，玩家精灵和整个场景（包括地图）出现轻微抖动
  • 特点：
    • 上下左右移动时不抖动
    • 只有斜方向移动时抖动
    • 去除 Camera2D 后精灵依然抖动
    • 去除 .normalized() 后依然抖动
    • 加上 Camera2D 后地图也跟着抖动

# 问题根因分析

# 亚像素位置渲染问题

# 数据流分析

# 问题核心

  1. 亚像素位置：position 不断累加小数位，产生如 726.1785 这样的亚像素坐标
  2. 渲染抖动：Sprite2D 在亚像素位置渲染时，GPU 需要进行像素插值，导致视觉上的抖动
  3. 4倍放大效应：
    • 项目视口：480x270
    • 窗口分辨率：1920x1080
    • 放大倍数：4x
    • 亚像素误差 0.178 像素被放大成 0.712 像素 → 肉眼可见的抖动
  4. 为什么斜方向更明显：
    • 上下左右移动时，只有一个轴产生亚像素（如 x 是整数，y 是小数）
    • 斜方向移动时，两个轴同时产生亚像素，抖动叠加效应更明显
  5. Camera2D 放大问题：
    • Camera2D 默认在 _process（渲染帧）更新
    • 玩家在 _physics_process（物理帧）更新
    • 两个阶段不同步时，Camera2D 读取的位置会"跳跃"
    • 导致整个场景跟着抖动

# 解决方案

# 方案：在 _physics_process 中将位置取整

# 修改文件：characters/player/script/player.gd

func _physics_process(delta):
	move_and_slide()
	# 将位置对齐到整数像素，消除斜方向亚像素抖动
	position = position.round()

# 原理

  • round() 将 position 强制对齐到最近的整数像素
  • 例如：(726.1785, 293.1785) → (726.0, 293.0)
  • 消除亚像素后，Sprite2D 在整数像素位置渲染，不再产生抖动

# 潜在问题

# 碰撞体边缘滑动

使用 position.round() 后，如果玩家在碰撞体边缘移动，可能出现：

  • 轻微的"滑动"感
  • 在障碍物角落卡住

# 替代方案（如果出现碰撞问题）

如果后续遇到碰撞问题，可以改用只对 Sprite2D 取整：

func _physics_process(delta):
	move_and_slide()
	# 只对 Sprite2D 进行取整，不影响物理碰撞
	$Sprite2D.position = position.round() - position

# 测试验证

  • [x] 去除 Camera2D → 精灵依然抖动（确认问题在玩家本身）
  • [x] 去除 .normalized() → 依然抖动（确认不是归一化问题）
  • [x] 添加 position.round() → 抖动消失（确认是亚像素位置渲染问题）
