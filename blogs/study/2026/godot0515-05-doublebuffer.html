# 双缓冲：读写分离，告别撕裂

# 问题：一边读一边写

一个典型的游戏循环：

void GameLoop() {
    while (true) {
        Update();    // 写数据 —— 移动所有实体
        Render();    // 读数据 —— 绘制所有实体
    }
}

如果 Update 和 Render 交替太快，或者多线程下并发，就会出现撕裂：

帧1更新一半时 → 渲染线程开始读数据
→ 读到的数据：一半是更新前，一半是更新后
→ 画面撕裂：物体位置错位、颜色不对

2

# 例子：物理模拟

class PhysicsSystem {
    Vector3[] positions;   // 所有物体的位置

    void Update() {
        for (int i = 0; i < positions.Length; i++) {
            positions[i] += velocities[i] * dt;
            // 读到这里被 Render 中断？读到的是半更新数据！
        }
    }

    void Render() {
        for (int i = 0; i < positions.Length; i++) {
            DrawMesh(positions[i]);  // 可能读到错误数据
        }
    }
}

# 双缓冲的解决方案

准备两份缓冲区：

Buffer A（前台） ← 渲染线程读它
Buffer B（后台） ← 逻辑线程写它
1
2

写的时候写后台，读的时候读前台，互不干扰。写完后台后交换角色。

[帧开始]
  Buffer A: 第 n 帧数据   ← Render 读
  Buffer B: 逻辑线程写入   ← Update 写
[Update 写完]
  交换 A ↔ B
[下一帧]
  Buffer B: 第 n+1 帧数据  ← Render 读
  Buffer A: 逻辑线程写入   ← Update 写

# 基本实现

class DoubleBuffer<T> {
    T[] buffers = new T[2];
    int current = 0;

    public T Read() => buffers[current];

    public T Write() => buffers[1 - current];

    public void Swap() {
        current = 1 - current;
    }
}

# 应用在游戏循环

class GameWorld {
    DoubleBuffer<GameState> stateBuffer = new();

    void Update() {
        var state = stateBuffer.Write();  // 写后台缓冲区
        state.entities.ForEach(e => e.Update());
        state.physics.Simulate();
        stateBuffer.Swap();              // 交换，让新数据可见
    }

    void Render() {
        var state = stateBuffer.Read();  // 读前台缓冲区
        state.entities.ForEach(e => RenderMesh(e));

}

# 双缓冲的变体

# 1. 三缓冲（Triple Buffering）

在双缓冲基础上加一块缓冲区：

Buffer A：渲染线程正在读
Buffer B：逻辑线程刚写完
Buffer C：逻辑线程正在写
1
2
3

优势：逻辑线程不需要等渲染线程读完就能开始写下一帧。适合垂直同步开启的场景。

实际效果：帧率波动时，三缓冲比双缓冲更平滑，但会增加 1 帧的输入延迟。

# 2. 脏标记 + 局部双缓冲

不需要整个状态都双缓冲，只对可能产生读写冲突的部分做缓冲：

class Transform {
    // 前台：渲染用
    Vector3 renderPosition;
    Quaternion renderRotation;

    // 后台：逻辑用
    Vector3 logicPosition;
    Quaternion logicRotation;
    bool dirty;

    void Commit() {
        renderPosition = logicPosition;
        renderRotation = logicRotation;
        dirty = false;
    }
}

# 3. 无锁双缓冲（Atomic Swap）

在多线程环境下，交换指针用原子操作：

class LockFreeDoubleBuffer<T> {
    T[] buffers = new T[2];
    volatile int readIndex = 0;

    public T Read() => buffers[readIndex];

    public T Write() => buffers[1 - readIndex];

    public void Swap() {
        Interlocked.Exchange(ref readIndex, 1 - readIndex);
    }
}

# 游戏中的实际应用场景

# 场景一：渲染管线（最经典）

GPU 正在渲染 Frame N  ← 读前台
CPU 准备 Frame N+1 的 Draw Call  ← 写后台

这是图形 API 内置的机制。SwapChain.Present() 就是 Buffer Swap。

双缓冲输入：

class InputSystem {
    InputState[] frames = new InputState[2];
    int current = 0;

    void PollInput() {
        var next = 1 - current;     // 往后台写
        frames[next].UpdateFromHardware();
        current = next;             // 交换
    }

    bool GetKeyDown(KeyCode k) {
        return frames[current].IsKeyDown(k) &&
               !frames[1 - current].IsKeyDown(k);
    }
}

# 场景三：AI 决策

AI 的决策结果和当前帧的执行分开：

class AISystem {
    DoubleBuffer<AIDecision> decisionBuffer;

    void Think() {
        var decisions = decisionBuffer.Write();
        foreach (var ai in ais) {
            decisions[ai.id] = ai.Think();
        }
        decisionBuffer.Swap();
    }

    void Execute() {
        var decisions = decisionBuffer.Read();
        foreach (var ai in ais) {
            ai.Execute(decisions[ai.id]);
        }
    }
}

# 《我的世界》光照更新

光照计算是多线程的，计算完一批 chunk 的光照后 Swap 到可见缓冲区，主线程渲染时不会读到"一半亮一半暗"的 chunk。

# 什么时候需要双缓冲

场景 需要？ 原因
单线程游戏循环 通常不需要 Update 完才 Render，没有竞争
多线程渲染 必须 GPU 和 CPU 并行，不缓冲会撕裂
输入系统 建议 需要对比上一帧状态判断按下/抬起
网络状态同步 建议 接收和插值不在同一帧
物理模拟 看情况 可以用，但多数引擎把物理和渲染放在同一帧

# 代价

  • 内存翻倍 — 需要存两份数据
  • 延迟增加 — 最多增加 1 帧的延迟（三缓冲更多）
  • 复杂度 — Swap 时机必须精准，避免读写到一半被切换

一句话总结： 双缓冲的本质是"写时不读，读时不写"。在 GPU/CPU 并行、网络同步、输入处理这三个场景里，它是不可绕开的基础设施。
